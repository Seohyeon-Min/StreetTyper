This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

StreetTyper is a Unity project (Editor version **6000.3.19f1**, Universal Render Pipeline, 2D template). The project is in a very early/scaffolded state: there is a single placeholder script and no gameplay code yet, so there is no established architecture to follow — treat early additions as the ones that will set the conventions for the rest of the project.

Do not assume a "typing game" architecture beyond what the project name implies — the default `InputSystem_Actions.inputactions` asset still has the generic Unity template action maps (Move, Look, Attack, Interact, Crouch, Jump, Sprint, etc.), not typing-specific bindings. Update or replace these action maps rather than assuming they're final.

## Working with this repository

This is a Unity project, not an npm/CLI project — there are no build/lint/test scripts to invoke from the terminal. Standard Unity workflow applies:

- **Editor**: Open the project root in Unity Hub / Unity Editor `6000.3.19f1` (must match `ProjectSettings/ProjectVersion.txt`; a mismatched editor version will trigger an upgrade prompt).
- **Compiling scripts**: Unity compiles C# automatically when the Editor regains focus, or via `Assets > Reimport` / `Ctrl+R`. There is no standalone `dotnet build` step for this project — `Assembly-CSharp.csproj` and `StreetTyper.sln` are auto-generated by Unity on each domain reload and should never be hand-edited (they're also gitignored).
- **Tests**: The `com.unity.test-framework` package is installed but no test assemblies/scripts exist yet. When adding tests, use Unity Test Runner (`Window > General > Test Runner`) with EditMode/PlayMode test assemblies (`.asmdef`), and run via the Editor GUI or `Unity.exe -runTests -testPlatform <EditMode|PlayMode> -projectPath . -testResults <path>` in batch mode.
- **Running the game**: Press Play in the Editor. There is no headless/CLI run path set up yet.

## Project structure

Assets are organized under numbered top-level folders (controls asset browser ordering):

- `Assets/00_Scenes/` — Unity scenes. `SampleScene.unity` is currently the only scene.
- `Assets/01_Arts/` — art assets (currently empty).
- `Assets/02_Scripts/` — C# scripts, all compiled into the implicit `Assembly-CSharp` assembly (no `.asmdef` split yet). Currently contains only an unmodified Unity script template (`InputManager.cs`, class `NewMonoBehaviourScript` — filename and class name don't match and no input logic has been implemented yet).
- `Assets/03_Prefabs/` — prefabs (currently empty).
- `Assets/04_Data/` — data assets, e.g. ScriptableObjects (currently empty).
- `Assets/Settings/` — URP render pipeline assets (`UniversalRP.asset`, `Renderer2D.asset`) and scene templates.
- `Assets/InputSystem_Actions.inputactions` — the new Input System's action map asset (see note above: still the default template).

Follow the existing `NN_Name` numeric-prefix convention when adding new top-level Assets folders.

## Conventions

- Target framework per `Assembly-CSharp.csproj`: C# `LangVersion 9.0`, .NET Standard 2.1 (Unity's Mono-based scripting backend) — avoid newer C# syntax that Unity's compiler won't accept.
- Uses the new **Input System** package (`com.unity.inputsystem`), not the legacy `UnityEngine.Input` API — write new input handling against `InputSystem_Actions` / generated `InputAction` bindings.
- 2D project using URP — prefer 2D-specific components/renderers (Sprite, Tilemap, 2D physics/lighting) over 3D equivalents.
